# ¥9.90 支付核验与下载交付

## 目标与当前边界

购买者只能在真实订单支付成功、订单金额核对为人民币 990 分后下载。网页显示 3 秒成功确认后尝试自动下载，并保留手动下载入口。3 秒是成功提示时间，不是支付机构到账或回调时延保证。

现有页面部署在 GitHub Pages，只有静态文件，没有服务端回调、订单数据库或私有文件权限控制。个人收款码图片不能提供订单接口凭据，也不能建立当前浏览器与某笔到账的可信对应关系。

用户提供的微信、支付宝图片在对话中可见；系统指定附件目录目前不存在，原图尚不可供本地程序读取。不能根据预览重绘收款二维码。收到原图文件后应裁出码体、保留至少四个模块宽的白色静区，并验证裁剪前后解码内容一致。

## 采用方案

采用微信支付 Native API v3、支付宝当面付订单接口：

1. 服务端创建随机订单号，固定商品和金额 990 分，绑定当前浏览器的 HttpOnly 会话。
2. 调用支付渠道创建订单，展示该订单的动态二维码，金额由服务端设置。
3. 渠道通知服务端。微信先对原始请求体验签，再解密 AES-GCM 通知；支付宝通过官方 SDK 验签。
4. 验签成功后核对渠道、商户、应用、订单号、金额、币种及交易终态；数据库事务内幂等入账，保存唯一渠道交易号。
5. 页面每 3 秒查询自己的订单。回调延迟时服务端主动查单补偿，支付机构错误或超时不能视为支付成功。
6. 状态为已支付后显示 3 秒确认，调用受保护下载接口。下载时再次校验会话、订单归属、支付状态及金额。
7. ZIP 保存在公开站点之外，禁止放到 GitHub Pages、公开仓库或无鉴权静态目录。浏览器阻止自动下载时，可在已支付订单页手动重试。

未提供商户配置、后端地址或私有安装包时，关闭支付下单和下载，页面显示通道尚未开通。不能以倒计时结束、点击“已付款”、支付截图或浏览器跳转冒充到账。

## 部署边界

- 支付后端应部署到有 HTTPS 域名、持久磁盘和出站网络的服务器；需接收公网支付通知。
- GitHub Pages 保留商品介绍；设置支付站点地址后跳转到支付服务器上的同源结算页。避免依赖跨站第三方 Cookie，兼容手机浏览器。
- 支付页和订单 API 同源，使用 Secure、HttpOnly、SameSite 会话 Cookie。服务端验证 Origin，订单查询与下载逐次校验归属。
- 微信商户号、应用 ID、商户签名私钥、商户证书序列号、API v3 密钥、微信支付公钥及公钥 ID均从服务器配置读取。
- 支付宝应用 ID、应用私钥、支付宝公钥与卖家 ID 从服务器配置读取。
- 密钥、支付数据库和私有 ZIP 不得提交仓库。只有配置说明和示例键名可公开。
- 个人收款码只能做人工收款展示，不能代替上述动态订单码。若使用第三方聚合支付，也仍需真实的商户 API 与签名回调凭据。

## 必须验证的行为

- 未付款、金额少付/多付、币种不符、订单不符、商户不符、伪造签名时均拒绝下载。
- 重复回调、并发回调只能记账一次；同一交易号不能兑换多个订单。
- 前端传入 `paid=true`、改价格、猜订单号或换会话均不能解锁下载。
- 回调未到但主动查单确认成功时可正常交付；支付未确认时持续等待，不能限时自动成功。
- 关闭弹窗、切换支付方式、刷新、手机支付后返回时正确恢复原有订单，避免重复扣款。
- 私有文件缺失时不开放新订单，错误信息不泄露路径、密钥或交易原始报文。
- 测试与联调结果必须区分；没有真实商户配置，不能宣称已完成真实收款验证。

## 已实现的接口与文件

- `GET /api/checkout`：创建签名 HttpOnly 会话，返回可用渠道和已有订单。
- `POST /api/orders`：只接收支付方式；价格始终为 990 分。当前浏览器已有待付或已付订单时复用，不创建第二笔。
- `GET /api/orders/:id`：只查自己的订单；每单最多约 10 秒调用一次渠道查单。
- `POST /api/notify/wechat`、`POST /api/notify/alipay`：验签、核验、幂等入账。
- `GET /api/orders/:id/download`：再次校验会话和付款状态，且至少在到账记录写入 3 秒后提供附件。
- SQLite WAL 保存订单，渠道交易号有唯一约束。浏览器会话有效期 30 天；清除 Cookie 或换浏览器不能恢复下载，需运营人工核对订单。
- 公开页面只有空的支付地址配置；没有测试支付成功按钮、模拟回调路由或前端解锁开关。
- `scripts/crop-payment-qr.py` 仅裁剪可读原图并核对解码内容，不重绘二维码、不改变收款人。

## 部署与联调

1. 使用 Node.js 22.16+，在 `payment-service` 执行 `npm ci`。复制 `.env.example` 为服务器上的 `.env`，设置至少 32 字节随机会话密钥。
2. 商户应已开通微信 Native / 支付宝当面付对应产品。配置文件中的私钥、公钥路径来自自己的商户平台。只配置一个渠道时仅开放该渠道；个人码图片不能提供这些凭据。
3. 支付服务器使用独立 HTTPS origin，例如 `https://pay.example.com`。反向代理将所有请求转发至 `127.0.0.1:8787`，原样保留回调体、Cookie 和 Origin；不要缓存 `/api/` 或 `/checkout-config.js`。
4. `DATABASE_FILE` 指向持久目录并定期备份；`DOWNLOAD_FILE` 指向仓库以外的实际安装 ZIP。进程使用专用非 root 用户，仅该用户可读密钥和安装包。单实例运行，避免跨实例丢失临时查询限流状态。
5. `npm start`。验证两条公网 HTTPS 通知 URL 均能由平台访问，维护微信公钥 ID 和平台公钥轮换。服务未配置渠道或安装包时不能创建支付订单。
6. 各渠道各做一笔真实 ¥9.90 小额验收，核对商户账单、订单记录、真实交易号和 ZIP 内容。覆盖手机扫码后切回浏览器、刷新恢复、重复通知、通知丢失后主动查单，以及浏览器拦截下载时手动重试。
7. **真实验收通过后**才在公开站点 `checkout-config.js` 填写支付 origin，并发布。当前未提供商户凭据及服务器，不能完成该步或宣称真实收款已接通。

会话密钥长期保持稳定，轮换会使已有浏览器下载权限失效。不要将示例域名作为真实回调地址，也不要将服务器 `.env`、数据库、私钥或安装包放进 GitHub Pages。

## 金额与异常处理

- 核对订单总额以及付款人实际支付金额均为 990 分。红包、抵扣等导致实际付款不足 ¥9.90 时不会自动放行；需商户人工处理退款或补偿，不能靠更改网页状态绕过。
- 创建订单超时可能已在平台成功，服务保留订单并查单，不自动生成新订单。如果始终无二维码、平台也查不到订单，运营必须先在商户平台确认未支付、关闭旧交易后才能人工处理；当前没有危险的后台“一键已支付”接口。
- 订单仅在渠道明确返回关闭终态时允许重新下单。浏览器显示等待时间长并不代表失败或自动成功。
- 自动保存受浏览器策略影响，因此保留手动重试。已付款时文件暂时不可用会显示错误，不引导重复购买。
- 支付流水只保存必要字段，不保存通知原文、完整支付账号、付款截图或简历。生产运行仍需配置日志、备份和异常订单人工处理。

## 官方依据

检索日期：2026-11-21。

- [微信 Native 支付接入易错点](https://pay.weixin.qq.com/doc/v3/merchant/4054257695)：下单返回 `code_url`，二维码由商户生成；回调地址须符合要求。
- [微信支付公钥验签](https://pay.weixin.qq.com/doc/v3/merchant/4013053249)：按应答头公钥 ID 核对验签，验签失败不能继续。
- [微信开发接入检查用例](https://pay.weixin.qq.com/doc/v3/merchant/4061593820)：应答与回调均要验签，核对本地订单、金额、商户和应用。
- [支付宝当面付接入注意事项](https://opendocs.alipay.com/open/194/105322)：独立商户订单号、服务端转发、异步验签和字段核对。
- [支付宝同步与异步通知区别](https://opendocs.alipay.com/support/01raw5)：前台跳转不可靠，最终状态以通知或查询接口为准。
- [支付宝异步通知说明](https://docs.open.alipay.com/204/105301/)：通知与主动查单同时接入，防止重复付款与单边账。
- [支付宝官方 Node.js SDK](https://github.com/alipay/alipay-sdk-nodejs)：API 请求、返回验签和 `checkNotifySignV2` 通知验签；公钥必须配置。
